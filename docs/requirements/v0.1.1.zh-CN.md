# TraceHub v0.1.1 需求

[English](v0.1.1.md) | [简体中文](v0.1.1.zh-CN.md)

状态：Draft

## 目标

TraceHub 与 Codex 本地活跃会话保持一致，不上传或保留归档会话。用户可以跨设备
浏览会话、明确永久删除会话，并将共享会话恢复到 Codex 后继续或分叉。

## 会话语义

TraceHub 只共享设备当前 `sessions` 中存在的活跃会话，不保存服务端归档状态。

| Codex 本地操作 | TraceHub 可观察行为 |
|---|---|
| 创建会话 | 共享完整会话 |
| 继续会话 | 共享新增的完整记录 |
| 归档会话 | 从 TraceHub 删除会话 |
| 取消归档 | 将会话作为活跃会话重新共享 |
| 永久删除会话 | 从 TraceHub 删除会话 |
| 分叉会话 | 共享新会话并保留 fork 关系 |
| 恢复会话 | 将原始会话写回目标设备的 `sessions` |

## 需求

### REQ-008：只共享活跃 Codex 会话

状态：Draft

用户可以让 TraceHub 只共享 Codex 的活跃会话，而不上传或保留本地归档会话。

验收条件：

- 默认同步来源仅为配置的 Codex 根目录下的 `sessions`。
- `archived_sessions` 中的文件不会被读取、上传或显示为共享会话。
- 新建和继续的活跃会话分别能够完整共享和增量共享。
- 同一份未变化的活跃会话重复同步不会产生重复会话或重复事件。

### REQ-009：对齐本地会话移除和恢复

状态：Draft

一次成功同步后，TraceHub 中由该设备共享的会话集合与该设备当前的活跃会话集合
一致。本地归档和永久删除在 TraceHub 中都表现为删除；取消归档后可以重新共享。

验收条件：

- 会话从 `sessions` 消失后，下一次成功同步会删除该设备在 TraceHub 中对应的会话。
- 删除会同时使会话正文、搜索索引、工具输出和导出结果不可访问。
- 会话从归档恢复到 `sessions` 后，下一次同步可以从头重新共享。
- 一台设备的同步不能删除另一台设备共享的会话。
- 重复同步相同的活跃会话集合是幂等的。

### REQ-010：删除对齐必须安全失败

状态：Draft

只有客户端能够证明本轮活跃会话发现和同步完整成功时，TraceHub 才能根据本地
会话集合执行删除。

验收条件：

- Codex 根目录或 `sessions` 不存在、不可读或扫描中断时，不删除服务端会话。
- 会话身份无效、文件重复、文件解析失败或同步上传失败时，不执行本轮删除对齐。
- 服务端未完整接受本轮活跃会话集合时，不执行本轮删除对齐。
- 失败会明确报告，并且不能把空集合或不完整集合解释为用户删除了全部会话。
- 上传失败的会话不能在同一轮同步中被误判为已删除。

### REQ-011：浏览和理解共享会话

状态：Draft

经过授权的用户可以跨设备浏览、搜索、筛选和分页阅读共享会话，并理解会话的
来源和 fork 关系。

验收条件：

- 用户可以列出会话、执行文本搜索并查看单个会话详情。
- 用户可以按来源设备、时间范围、工作上下文和是否为 fork 筛选会话。
- 列表和详情标明会话 UUID、来源设备、时间范围、工作上下文和最后同步时间。
- 存在 fork 信息时，详情标明父会话以及可查询的派生关系。
- 长会话可以使用稳定游标分页阅读，保持事件顺序且不重复或遗漏正文。
- 用户消息、Assistant 消息和工具活动保持可区分；reasoning 不通过浏览接口返回。
- 完整工具输出只在用户明确读取时返回，并遵守单次响应大小限制。
- 所有历史内容继续明确标记为不可信数据。

### REQ-012：明确永久删除共享会话

状态：Draft

经过授权的用户可以永久删除一个共享会话，但系统必须在执行前要求明确确认。

验收条件：

- 删除操作明确标识来源设备和会话 UUID，并要求不可省略的确认。
- 删除完成后，会话不能再通过列表、搜索、详情、分页阅读、工具输出或导出访问。
- 删除失败不会留下正文、索引或归档只删除一部分的状态。
- 来源设备上未变化的本地文件不能在下一次普通同步时静默恢复一个明确永久删除的会话。
- 用户可以执行明确的重新共享操作，允许仍然存在或再次恢复的本地会话从头上传。
- 删除确认信息不得包含完整会话正文。

### REQ-013：将共享会话恢复到 Codex

状态：Draft

用户可以在目标设备上下载一个共享会话并恢复到 Codex，使 Codex 能够继续该会话
或从该会话创建 fork。

验收条件：

- 恢复结果逐字节匹配 TraceHub 保存的原始完整 JSONL 记录。
- 恢复文件写入目标 Codex 根目录下的标准 `sessions` 位置，而不是
  `archived_sessions`。
- 下载、解密、校验或写入失败时，不留下 Codex 可见的半成品会话。
- 目标位置已有同 UUID 会话时明确失败，不覆盖现有文件。
- 恢复完成后，Codex 能发现该会话并允许用户继续或分叉。
- 恢复后的新增内容和 fork 会话可以通过后续同步共享。
- TraceHub 保留原始来源设备、恢复目标设备和已知 fork 关系，且不自动合并不同
  设备上的会话内容。

## 范围外事项

- 上传或浏览 `archived_sessions`。
- 服务端归档状态、回收站或延迟删除。
- Web UI。
- 常驻后台同步或自动修改远程设备文件。
- 自动合并不同设备上的会话内容。
- Codex 之外的其他 Agent。
- 团队权限、多用户租户、高可用或分布式运行。

## 版本验收

- 使用合成 Codex JSONL 完成创建、追加、归档、取消归档和永久删除的端到端流程。
- 在扫描、解析和上传故障下验证服务端不会误删会话。
- 由设备 A 上传后，设备 B 能完成搜索、筛选、详情查看和多页阅读。
- 恢复结果与原始 JSONL 逐字节一致，并能被 Codex 发现。
- 删除后确认密文、派生事件、搜索结果、工具输出和导出均不可访问。
- `make check`、`actionlint` 和 `git diff --check` 全部通过。
