# TraceHub v0.2.0 需求

[English](v0.2.0.md) | [简体中文](v0.2.0.zh-CN.md)

状态：Draft

## 目标

TraceHub 与 Codex 本地活跃会话保持一致，且不同步已归档会话。用户可以跨设备
理解会话及 fork 关系，使明确永久删除的会话继续保持删除状态，并将共享会话
恢复到 Codex 后继续或分叉。

## 会话语义

一次同步成功后，设备共享到 TraceHub 的会话集合等于该设备当前 `sessions`
中的活跃会话集合，但排除根据 REQ-014 明确永久删除的会话。TraceHub 不保存
服务端归档会话状态。

| 操作 | TraceHub 可观察行为 |
|---|---|
| 在本地创建会话 | 共享其完整记录 |
| 在本地继续会话 | 共享新完成的记录 |
| 在本地归档或永久删除会话 | 删除该设备的共享副本 |
| 在本地取消归档 | 重新共享，除非该会话已被明确永久删除 |
| 明确永久删除共享会话 | 删除会话并抑制普通重新共享 |
| 明确重新共享会话 | 清除抑制并从头共享会话 |
| 在本地分叉会话 | 共享新会话并保留已知父关系 |
| 恢复共享会话 | 将已同步记录写入目标设备的 `sessions` 目录 |

## 需求

### REQ-008：只共享活跃 Codex 会话

状态：Draft

用户可以让 TraceHub 同步 Codex 的活跃会话，而不同步本地已归档会话。

验收条件：

- 同步只在已配置 Codex 根目录下的 `sessions` 中发现会话。
- 同步不读取或上传 `archived_sessions` 下的文件，这些文件也不显示为共享会话。
- 新建和继续的活跃会话分别能够完整共享和增量共享。
- 同一份未变化的活跃会话重复同步不会产生重复会话或重复事件。

### REQ-009：对齐本地会话移除和返回

状态：Draft

一次同步成功后，TraceHub 将一台设备共享的会话与该设备当前活跃会话集合对齐，
但排除根据 REQ-014 记录的明确永久删除。

验收条件：

- 会话从 `sessions` 消失后，下一次成功同步会删除该设备对应的共享会话。
- 删除会移除会话的加密源分块、派生事件和搜索索引项，并使详情、工具
  输出和导出不可用。
- 同一会话后续返回 `sessions` 时，下一次成功同步会从头共享它，除非 REQ-014
  对它实施了抑制。
- 一台设备的同步不能删除或抑制另一台设备共享的会话。
- 重复同步相同的活跃会话集合是幂等的。

### REQ-010：会话集合对齐必须安全失败

状态：Draft

只有客户端和服务端能确立本轮发现和同步完整成功时，TraceHub 才根据本地
活跃会话集合对齐删除。

验收条件：

- Codex 根目录或 `sessions` 不存在、不可读或扫描中断时，不删除服务端会话。
- 会话身份无效、文件重复、解析失败或上传失败时，不执行本轮删除对齐。
- 只有服务端接受该设备的完整活跃会话集合后，才执行删除对齐。
- 失败会明确报告；不能把不完整集合解释为用户删除了其中缺失的会话。
- 只有在完整扫描已存在且可读的 `sessions` 目录，并且服务端将空集合接受为
  完整集合后，有效空集合才能授权删除。
- 上传失败的会话不能在同一轮同步中被误判为已删除。

### REQ-011：浏览和理解共享会话

状态：Draft

经过授权的用户可以跨设备浏览、搜索、筛选、查看详情和分页阅读共享会话，并
理解会话的来源和 fork 关系。

验收条件：

- 用户可以按精确来源设备、与会话已知时间范围重叠的事件时间区间、来源报告的
  代码库或工作目录，以及会话是否存在已知父会话进行筛选。
- 列表和详情标明会话 UUID、来源设备、已知时间范围、来源报告的工作上下文
  和最后一次成功同步时间。
- 存在 fork 元数据时，详情使用来源设备和会话 UUID 标明父会话和直接子会话。
- 结果集不变时，列表游标保持确定顺序，并且在多页中每个匹配会话只返回一次。
- 会话在多次分页请求之间不变时，事件游标保持事件顺序，且不重复或遗漏正文。
- 用户消息、Assistant 消息和工具活动保持可区分；reasoning 不通过浏览接口返回。
- 完整工具输出只在用户明确请求时返回，每次响应最多返回 256 KiB。
- 所有历史内容继续明确标记为不可信数据。

### REQ-013：将共享会话恢复到 Codex

状态：Draft

经过授权的用户可以在目标设备上恢复共享会话，使 Codex 能够继续该会话或创建
fork。

验收条件：

- 恢复字节等于选定来源设备和会话 UUID 在最后一次成功同步中被接受的所有
  完整原始 JSONL 记录按顺序连接后的字节。
- 恢复文件写入目标 Codex 根目录下 `sessions` 中的标准日期路径，而不是
  `archived_sessions`。
- 写入前，TraceHub 会在目标 Codex 根目录下的 `sessions` 和 `archived_sessions` 中检查
  相同会话 UUID；任何位置已存在时都会拒绝恢复，且不覆盖现有文件。
- 下载、解密、校验或写入失败时，不留下 Codex 可见的半成品会话。
- 发布验证使用的 Codex 安装可以发现恢复后的会话，并允许用户继续或分叉。
- 恢复后创建的新完整记录和 fork 可以通过后续同步共享。
- 恢复文件后续被共享时，TraceHub 将原始贡献设备和目标设备识别为拥有相同会话
  UUID 的两份独立贡献；它保留已知 fork 关系，且不合并两份内容。

### REQ-014：使明确永久删除的会话保持删除状态

状态：Draft

经过授权的用户可以明确永久删除一台设备共享的会话，并阻止普通同步在用户
明确重新共享前静默恢复本地副本。

验收条件：

- 明确永久删除标识来源设备和会话 UUID，只保存抑制普通重新共享所需的身份
  信息，不保存会话内容。
- 明确永久删除后，即使未变化的本地文件仍在 `sessions` 中或后续返回该目录，
  普通同步也会使会话保持删除状态。
- 一台来源设备的抑制不会影响另一台设备上具有相同会话 UUID 的贡献。
- 明确重新共享必须指定来源设备和会话 UUID；不存在匹配的本地活跃文件时明确
  失败，否则清除抑制，使下一次成功同步从头共享会话。
- 永久删除失败时，会话和原有抑制状态保持不变；重新共享失败时，保留抑制。
- 抑制不会自动过期，直到用户明确重新共享。

## 范围外事项

- 上传或浏览 `archived_sessions`。
- 服务端归档会话状态、回收站或延迟删除。
- Web UI。
- 常驻后台同步或自动修改远程设备文件。
- 自动合并不同设备上的会话内容。
- Codex 之外的其他 Agent。
- 团队权限、多用户租户、高可用或分布式运行。

## 版本验收

- 使用合成 Codex JSONL 完成创建、追加、归档、取消归档和本地删除的端到端流程。
- 验证发现、解析、上传和服务端接受故障不会导致服务端会话被删除；另外独立
  验证完整扫描后的有效空集合。
- 明确永久删除会话，验证普通同步使其保持删除状态，然后明确重新共享，并验证
  下一次成功同步从头共享它。
- 设备 A 上传父会话和 fork 后，设备 B 能完成筛选、查看关系和多页阅读；数据不变时，
  结果不重复也不遗漏。
- 恢复最后一次成功同步所接受的记录，验证精确字节、Codex 发现和 UUID 冲突拒绝。
- 删除后确认加密源分块、派生事件、搜索结果、工具输出和导出全部不可用。
- `make check`、`actionlint` 和 `git diff --check` 全部通过。
