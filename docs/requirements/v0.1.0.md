# TraceHub v0.1.0 Requirements

[English](v0.1.0.md) | [简体中文](v0.1.0.zh-CN.md)

Status: Accepted

## Goal

A user can install TraceHub, share Codex session history from multiple devices,
and retrieve an authorized session from another device.

## Requirements

### REQ-001: Identify a source device

Status: Accepted

A user can configure a stable logical identity for each device that contributes
sessions. Session results identify their source device without exposing a device
IP address as its identity.

Acceptance criteria:

- Two configured devices are distinguishable in uploaded and queried sessions.
- An unconfigured or invalid device identity fails explicitly.

### REQ-002: Share complete Codex session history

Status: Accepted

A user can submit the complete original history of a locally stored Codex
session. Repeating the same submission does not create a duplicate session.

Acceptance criteria:

- A valid Codex session can be submitted and later identified by session ID and
  source device.
- The preserved session can reproduce the submitted original record.
- Repeating an unchanged submission leaves one logical session record.
- Invalid complete records and an invalid or incomplete first record fail
  explicitly without being reported as shared.
- An incomplete trailing record remains local until completed and is not
  reported as shared by the current synchronization.

### REQ-003: Continue sharing a growing session

Status: Accepted

A user can submit new history added to a previously shared Codex session without
having to create a second logical session.

Acceptance criteria:

- Newly completed session records become available after another submission.
- Previously shared records remain unchanged and in order.
- A source history that is truncated or rewritten fails explicitly instead of
  being silently joined to the existing history.

### REQ-004: Discover sessions across devices

Status: Accepted

An authorized user can list and search shared sessions by source device, time,
repository or working context, and text query.

Acceptance criteria:

- Results from at least two source devices can be returned in one query.
- Each result identifies its session, source device, time range, and working
  context when the source contains that information.
- A query with no matches returns an empty result rather than an error.

### REQ-005: Read a shared session

Status: Accepted

An authorized user can read a selected session without requiring the complete
history to be returned in one response.

Acceptance criteria:

- User messages, assistant messages, and tool activity remain distinguishable.
- A long session can be read in bounded parts while preserving event order.
- The reader can continue from the last returned part without duplicate events.

### REQ-006: Restrict session access

Status: Accepted

Session submission and retrieval are available only to configured, authorized
participants. A denied operation does not return session content.

Acceptance criteria:

- Unauthorized submission and retrieval both fail explicitly.
- Data changed after leaving its source device is detected before it is accepted
  as a valid original session.
- Ordinary logs and error responses do not include complete session content or
  credentials.

### REQ-007: Provide installable release artifacts

Status: Accepted

The stable `v0.1.0` release provides documented artifacts that allow a user to
install the required TraceHub parts and complete the supported multi-device flow.

Acceptance criteria:

- Release artifacts include SHA-256 checksums.
- A clean installation from only the published artifacts succeeds on every
  platform declared by the release.
- The installed release completes submission, cross-device discovery, and
  session reading using Codex session history.

## Out of scope

- Agents other than Codex.
- Multiple independent tenants or public registration.
- High availability or distributed operation.
- Continuous background synchronization.
- Stable compatibility guarantees before `v1.0.0`, except that a patch release
  must not intentionally break behavior from the same minor version.
