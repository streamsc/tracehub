# TraceHub v0.1.0 需求

[English](v0.1.0.md) | [简体中文](v0.1.0.zh-CN.md)

状态：Accepted

## 目标

用户可以安装 TraceHub，从多台设备共享 Codex 会话历史，并从另一台设备读取
经过授权的会话。

## 需求

### REQ-001：标识来源设备

状态：Accepted

用户可以为每台提交会话的设备配置稳定的逻辑身份。会话查询结果能够标明来源
设备，但不使用设备 IP 地址作为身份。

验收条件：

- 两台已配置设备在上传和查询的会话中能够明确区分。
- 未配置或无效的设备身份会明确失败。

### REQ-002：共享完整 Codex 会话历史

状态：Accepted

用户可以提交本地保存的 Codex 会话完整原始历史。重复提交相同内容不会产生
重复会话。

验收条件：

- 有效 Codex 会话可以提交，并能通过会话 ID 和来源设备再次识别。
- 保存的会话能够还原提交时的原始记录。
- 重复提交未变化的内容后仍只有一条逻辑会话记录。
- 无效的完整记录以及无效或不完整的首条记录会明确失败，且不会被报告为共享成功。
- 末尾未完成记录留在本地等待补全，本次同步不得将其报告为已共享。

### REQ-003：继续共享增长中的会话

状态：Accepted

用户可以继续提交已共享 Codex 会话中新增的历史，而无需创建第二条逻辑会话。

验收条件：

- 再次提交后，新增的完整会话记录可以被读取。
- 已共享记录保持内容不变且顺序不变。
- 来源历史被截断或重写时会明确失败，不会静默拼接到已有历史。

### REQ-004：跨设备发现会话

状态：Accepted

经过授权的用户可以按来源设备、时间、仓库或工作上下文以及文本查询列出和
搜索已共享会话。

验收条件：

- 一次查询可以返回至少两台来源设备的结果。
- 当来源包含相应信息时，每条结果标明会话、来源设备、时间范围和工作上下文。
- 没有匹配项的查询返回空结果，而不是错误。

### REQ-005：读取共享会话

状态：Accepted

经过授权的用户可以读取选定会话，而无需在一次响应中返回完整历史。

验收条件：

- 用户消息、Assistant 消息和工具活动能够明确区分。
- 长会话可以按有界的多个部分读取，同时保持事件顺序。
- 读取方可以从上次返回位置继续，且不会重复事件。

### REQ-006：限制会话访问

状态：Accepted

只有已配置且经过授权的参与方可以提交和读取会话。被拒绝的操作不会返回会话内容。

验收条件：

- 未授权的提交和读取都会明确失败。
- 数据离开来源设备后发生的变化会在其被接受为有效原始会话前被检测出来。
- 常规日志和错误响应不包含完整会话内容或凭据。

### REQ-007：提供可安装发布产物

状态：Accepted

稳定版 `v0.1.0` 提供有文档说明的产物，使用户能够安装 TraceHub 所需部分，
并完成受支持的多设备流程。

验收条件：

- 发布产物包含 SHA-256 校验文件。
- 仅使用发布产物即可在发布声明的每个平台上完成全新安装。
- 安装后的版本可以使用 Codex 会话历史完成提交、跨设备发现和会话读取。

## 范围外事项

- Codex 之外的其他 Agent。
- 多个独立租户或公开注册。
- 高可用或分布式运行。
- 持续后台同步。
- `v1.0.0` 之前的稳定兼容保证；但补丁版本不得故意破坏同一次版本已有行为。
